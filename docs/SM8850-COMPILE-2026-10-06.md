# SM8850 编译链调优

目标仍为固定的 Xiaomi 17 / `OS4.0.0.9.XPCCNXM`，Image 源码仍为九月 KMI6 common `0316e9866fdf`。全部 pin、来源和参考摘要以根目录 `.env` 为准。

| 阶段 | 固定工具或策略 |
| --- | --- |
| C / LLVM / LLD | AOSP Clang r596125，22.0.2 |
| Rust | AOSP `1.97.0` 子树；实际为 1.97.0-dev / LLVM 22.1.6 |
| bindgen | AOSP 预编译 0.72.1，单文件 Git blob 校验 |
| 内核辅助工具 | 最新固定 kernel build-tools 的 `linux_musl-x86` 子树 |
| 宿主 bc | AOSP gavinhoward-bc 7.0.3，单文件 Git blob 校验 |
| IPSet 用户态 | NDK r30 / 30.0.16248370，API 35 |

Clang 来自固定 AOSP Git 提交，其完整上游子树必须对应 Git tree `44e59376d6231e87e4ba5545c6baa619b6d4ad54`。Clang 仅检出编译器、资源头文件、x86_64 GNU 宿主库及相关头文件和许可证；Rust 仅检出编译器、宿主标准库、内核所需 library 源码和许可证。两者的 Git tree pin 对应完整上游子树，文件树 SHA-256 对应 `init.sh` 明确列出的稀疏内容，安装树再独立校验。Rust 安装在独立的 `rust/`，保留 Rust 与 Clang 各自的 LLVM 共享库。

原生 Kconfig 要求 Clang 与 Rust 使用同一 LLVM 主版本才能启用 inline helpers。因此采用固定 AOSP 提交内最新的 LLVM 22 Clang，与 Rust LLVM 22 配套；构建必须确认 `RUSTC_CLANG_LLVM_COMPATIBLE=y` 和 `RUST_INLINE_HELPERS=y`。

C 使用 `-march=armv9.1-a+fp16fml+crypto+sve2-aes+sve2-sha3+sve2-sm4+sme+rcpc3+rng -mtune=oryon-1`。Rust 使用 generic ISA 基底、`-Ztune-cpu=oryon-1` 和 `.env` 完整特性声明，末尾保留 `-neon`。Oryon-1 是现有调度代理，不代表精确建模第三代 Oryon。

普通 C 路径继续由 Kbuild 的 `-mgeneral-regs-only` 约束。专用 SIMD 文件保留自己的规则；宿主、Arm32、纯汇编和 NDK 用户态不加入这组参数。Rust 保留 softfloat ABI、strict-align、fixed-x18、PAC 和 KCFI；`RUST_INLINE_HELPERS=y`，同时审查直接 Rust 对象与经 llvm-link / Clang 的合并 bitcode。输入中的 SME 声明保留，实际依赖处理以固定编译器输出为准，不手改 LLVM 属性。

保留 O2、LTO_NONE、固定 common AutoFDO profile 和既有安全配置。编译前检查 profile 来源、摘要及新 LLVM 的读取能力。构建先检查代表性实际对象，再完成 Image / modules；命令审计覆盖全部保存的编译阶段，检查最终 ISA、tune、profile 和宿主参数隔离，并检查 helper / Rust / 合并 IR 的调度属性及普通路径寄存器限制。上游刻意关闭 AutoFDO 的早期启动、vDSO、hyp、EFI stub 等路径及已经在生产者阶段使用 profile 的 bitcode 后端按原规则记录。

兼容 LLVM 22 组合已完成候选 Image 与 104 个模块的完整编译。固定 OTA 的 4083 项 tuple、102 个严格 system_dlkm 模块及 Rust Binder 精确 167/67 例外通过。七个代表性生产对象共检查 120337 条指令，未检出 FP、向量或 SME 状态寄存器使用。性能、功耗和固定 OTA 真机复测尚未完成；取证设备此前为 `.32` OTA，其结果不能替代 `.9` 的验收。

快照变化及逐项审查记录见 [结构化漂移清单](SM8850-COMPILE-2026-10-06.tsv)。配置由 8246 行变为 8249 行，13 个差异均为工具版本或能力探测；启动、模块、安全配置与 inline helpers 保留。全量 Module.symvers 由 19794 项变为 18592 项，vmlinux/STG 导出由 19196 项变为 17994 项，vendor 并集仍为 4740 项。首次构建的 10 项漂移和完整快照已保留，只有完成下面的兼容性审查后才刷新参考值。

Rust 原生导出生成规则保持原样：bindings 对象由 1192 个导出变为 0，core 由 435 变为 445，kernel 由 123 变为 103，合计减少 1202 项；1749 个旧名字移除、547 个新名字加入，全部来自这些自动生成头文件。目标闭包没有消费这些变化。唯一 C CRC 漂移为未被 OTA 消费的 `__traceiter_arm_event`：同一 gendwarfksyms 对旧、新对象展开后，仅 packed `cper_sec_proc_arm` 多出 DWARF `alignment(1)`，40 字节大小与所有成员偏移一致；源码原有 `#pragma pack(1)` 保留。

用同一新 STG 工具提取旧、新 Image 的全部 4083 项目标消费者，类型图逐字节一致，SHA-256 均为 `7aa3ecad888492399365f1b1446a48cc40accbc0b2c950ddc11c7aadc8479344`。全量共同类型差异另包括 bindgen 把 Rust 视图中的两处 `gen` 字段转义为 `gen_`，没有尺寸或偏移变化；新 STG 对旧 ELF 的对照仅修正两个 Rust 导出的枚举常量有符号表示。均不影响目标消费者类型。

全量共同函数中只有 `release_pages` 的 KCFI hash 变化。按实际整数规范化参数编译的小型对照精确复现：Clang 22 将透明联合参数按首成员指针规范化为 `9e2f0e99`；原 Clang 19 联合参数为 `5032ee2a`，普通指针参数为 `9e2f0e99`。该函数未被目标 OTA 闭包消费，现有内核引用均为直接调用；目标闭包中 3654 个具有 KCFI 前缀的函数逐项一致。

日志中 36 项 unknown/unstable 特性诊断来自上游 `rust_is_available.sh` 向宿主 `--print sysroot` 探测传入 KRUSTFLAGS。实际 arm64 探针仅保留五项已知 unstable-feature 诊断，最终命令及 IR 审查通过；未增加警告屏蔽。

本地保留当前 LLVM 22 工具链与增量构建，以及 LLVM 19 配套工具链和 `g1d7d3325` 通用构建作为一个回退基线。历史 V2 候选的产物、来源和审计证据归档后清理其完整构建缓存；失败下载、重复安装和孤立实验对象一并清理。固定源码与官方审计 Git 缓存、原始 OTA 输入和真机日志继续保留，避免重复下载。

隔离候选 `g23c426d9` 的产物与审计记录保留原身份。主仓库提交完成后复用已有物理构建目录进行一次增量验证，新产物必须由主仓库真实提交派生，不能改名冒充旧候选或沿用其真机验收结论。本地清理清单和验证记录保存在不入库的 `kernel_out/local-cleanup-2026-10-06/`。

实际对象预检复现了 Rust >= 1.91 的 bindings 空导出 / 无 DWARF 兼容问题，新增独立官方修复 [fdf302e6bea1](https://android.googlesource.com/kernel/common/+/fdf302e6bea1822a9144a0cc2e8e17527e746162)。修复只改变宿主 gendwarfksyms 对空符号输入的处理；非空导出继续要求有效 DWARF，固定 OTA 模块闭包与版本机制保持原门槛。完整性树摘要改用单进程计算，格式及既有有效树摘要保持一致，减少逐文件启动宿主进程的开销。
